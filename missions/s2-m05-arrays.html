MISSION 2.5: ARRAYS & ARRAY METHODS

map / filter / reduce

In Mission 2.3 you looped over arrays by hand — an index, a condition, a running total, all wired together with for statements. That works, but professionals rarely write it that way anymore. Arrays come with built-in methods that express exactly what you mean — "transform every item," "keep only the ones that match," "combine everything into one value" — without a single hand-rolled loop. This is the mission where a cargo manifest becomes something you can reshape, narrow down, and total up in three clean, readable steps.

🟡 OFFICER LEVEL ⏱ ~55 MIN 🛠 BROWSER ONLY
1

Briefing

Picture a cargo manifest for your ship — a list of every crate in the hold, each with a name and a weight. A loading officer might need to answer three completely different questions about that same list: "What's the handling cost of each item?" (a transformation), "Which items are actually over the weight limit?" (a narrowing-down), and "What's the total cost across everything that made the cut?" (a combination into one number). Those three questions map almost exactly onto JavaScript's three most important array methods: .map(), .filter(), and .reduce().

What makes these methods worth learning — beyond just being shorter than a for loop — is that each one has exactly one job, and its name tells you what that job is. When you read cargo.filter(...) in someone else's code, you instantly know a shorter list comes out the other end. A hand-written loop could be doing literally anything; you'd have to read every line to find out. That readability is a real engineering advantage, not just style preference.

They also share a quieter but equally important trait: .map(), .filter(), .reduce(), and .find() all return something new and leave the original array exactly as it was. That's called immutability, and it's the opposite of methods like .push() and .sort(), which change the original array in place. Knowing which category a method falls into will save you from some genuinely confusing bugs later.

One array, three stages: map transforms every item (still 6), filter drops the ones that don't qualify (down to 3), and reduce collapses what's left into a single answer.

Field Manual

Array Recap — Index, Length, Push & Pop

An array is an ordered list, indexed from 0. Before the fancier methods, three basics are worth re-grounding: reading by index, checking .length, and the two mutating methods that add or remove from the end of the array.

JAVASCRIPT
const cargo = [
  { name: "Oxygen Tanks", weight: 40 },
  { name: "Water Rations", weight: 25 },
  { name: "Titanium Plating", weight: 90 },
  { name: "Medical Kit", weight: 12 },
  { name: "Spare Thrusters", weight: 65 },
  { name: "Seed Vault", weight: 18 }
];

console.log(cargo[0]);       // { name: "Oxygen Tanks", weight: 40 }
console.log(cargo.length);   // 6

cargo.push({ name: "Spare Boots", weight: 4 }); // mutates! length is now 7
cargo.pop();                                     // mutates! back to 6
WHAT JUST HAPPENED cargo[0] reads the first object by index. .length is a live property, not a method — no parentheses. .push() and .pop() both change cargo directly, in place — no new array is created. That's the mutating category. Everything in the rest of this mission is the opposite category: it hands back a new array (or value) and leaves cargo alone.

.map() — Transform Every Item

.map() runs a function on every item in an array and collects whatever that function returns into a brand-new array — always the same length as the original, one output per input.

JAVASCRIPT
const costs = cargo.map(function (item) {
  return item.weight * 3; // 3 credits per kg
});

console.log(costs); // [120, 75, 270, 36, 195, 54]
console.log(cargo.length === costs.length); // true — always true for map
WHAT JUST HAPPENED The callback function runs once per item, in order. Whatever it returns becomes the matching item in the new array. cargo still has 6 objects with their original weight property untouched — costs is a completely separate array of 6 plain numbers.

.filter() — Keep What Matches

.filter() also runs a function on every item, but that function must return true or false. Items where it returns true survive into the new array; everything else is left out. The result can be shorter than the original — or just as long, or even empty.

JAVASCRIPT
const heavyCargo = cargo.filter(function (item) {
  return item.weight > 50;
});

console.log(heavyCargo.length); // 2
console.log(heavyCargo.map(item => item.name)); // ["Titanium Plating", "Spare Thrusters"]
WHAT JUST HAPPENED Only weight > 50 is checked, one item at a time: Oxygen Tanks (40) fails, Titanium Plating (90) passes, and so on. heavyCargo ends up with just the 2 items that passed — cargo is still 6 items, unchanged. Notice the second line chains a .map() straight onto the filtered result — that's completely normal; every array method returns an array, so you can immediately call another method on it.

.reduce() — Combining Everything

This is the one that trips people up, so slow down here. .reduce() walks through the array item by item, carrying a single running value — the accumulator — from one iteration to the next, and hands back whatever that accumulator ends up as after the last item.

It takes two arguments: a callback shaped (accumulator, currentItem) => newAccumulator, and a starting value for the accumulator. That second argument matters — always pass it.

JAVASCRIPT
const totalWeight = cargo.reduce(function (total, item) {
  return total + item.weight;
}, 0); // 0 is the starting value

console.log(totalWeight); // 250
WHAT JUST HAPPENED — TRACING THE ACCUMULATOR total starts at 0 (the second argument). Then, for each item, it becomes the return value of the callback — carried forward into the next call:

start: total = 0
Oxygen Tanks (40): total = 0 + 40 = 40
Water Rations (25): total = 40 + 25 = 65
Titanium Plating (90): total = 65 + 90 = 155
Medical Kit (12): total = 155 + 12 = 167
Spare Thrusters (65): total = 167 + 65 = 232
Seed Vault (18): total = 232 + 18 = 250

After the last item, .reduce() hands back the final accumulator — 250 — as a plain number, not an array. If you skip the 0, JavaScript uses the array's first item as the starting accumulator instead and starts looping from the second item — which works for simple sums but silently breaks the moment your accumulator needs to be a different shape than your items (like building a total from objects). Always pass the starting value explicitly.
▸ DEEP DIVE: Chaining all three into one pipeline

Because every one of these methods returns an array (except .reduce(), which returns whatever you build), you can chain them directly, one after another, in a single expression — no intermediate variables needed:

JAVASCRIPT
const totalSurcharge = cargo
  .map(item => item.weight * 3)     // -> [120, 75, 270, 36, 195, 54]
  .filter(cost => cost > 100)      // -> [120, 270, 195]
  .reduce((sum, cost) => sum + cost, 0); // -> 585

console.log(totalSurcharge); // 585

Read it top to bottom like an assembly line: raw items go in the top, a single number comes out the bottom. This is exactly the pipeline you'll drive by hand in the Command Console below.

.find() & Immutability

.find() returns the first item that matches a condition — not an array, just the item itself (or undefined if nothing matches). Use it when you want exactly one thing, not a filtered list.

JAVASCRIPT
const medKit = cargo.find(function (item) {
  return item.name === "Medical Kit";
});

console.log(medKit); // { name: "Medical Kit", weight: 12 }

const missing = cargo.find(item => item.name === "Laser Cannon");
console.log(missing); // undefined — always check for this
WHAT JUST HAPPENED .find() stops looking the moment it finds a match — it doesn't scan the whole array like .filter() does. And here's the immutability payoff for the whole mission: after every .map(), .filter(), .reduce(), and .find() call above, cargo.length is still 6. None of them ever touched the original array — only .push(), .pop(), and mutating methods like .sort() do that. When you're not sure which category a method falls into, check the docs — it's one of the most common sources of "why did my original data change?!" bugs.

▸ HINT

If your reduce total comes out wrong or crashes, check two things: did you actually pass a starting value as the second argument (usually 0), and does your callback return the new accumulator on every path? A callback with curly braces that forgets return silently hands back undefined, and undefined + anything turns your total into NaN.

Debrief / Cheat Sheet

arr.map(fn)New array, same length, transformed values
arr.filter(fn)New array, only items where fn returns true
arr.reduce(fn, start)Collapse the array into one accumulated value
arr.find(fn)First matching item, or undefined — never an array
arr.push() / .pop()Mutate the original array in place
arr.sort()Also mutates — sorts the original in place
immutability
 map/filter/reduce/find never change the original
arr.lengthLive property — no parentheses
a.map(f).filter(g)Methods chain because each returns an array

⚠ COMMON MISTAKES

  • Calling .reduce() without a starting value and getting a confusing result (or a crash on an empty array).
  • Expecting .map() or .filter() to change the original array — they don't; you have to store what they return.
  • Forgetting return inside a multi-line { } callback, silently turning every result into undefined.
  • Using .find() when you actually wanted .filter() (or vice versa) — one gives one item, the other gives an array.
  • Losing track of what the accumulator holds mid-reduce — when in doubt, trace it step by step like the Field Manual did.

Quick check — what does [].reduce((total, item) => total + item.weight, 0) return when called on an empty array?
