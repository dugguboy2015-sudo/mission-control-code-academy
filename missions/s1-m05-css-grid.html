MISSION 1.5: CSS GRID LAYOUT

Two-Dimensional Layout

Flexbox taught you to line elements up along a single direction — a row, or a column. But a real deck plan isn't a single corridor. It's rows AND columns at once, with rooms that span multiple cells. That's CSS Grid: the layout system built for arranging a page in two dimensions simultaneously. Same CSS language, new superpower.

🟢 CADET LEVEL ⏱ ~50 MIN 🛠 BROWSER ONLY
1

Briefing

Think about the difference between arranging crew along a single corridor and laying out an entire deck plan. Flexbox is the corridor: you pick one direction — a row or a column — and items line up along it, one after another. It's one-dimensional. Excellent for a navbar, a button group, a sidebar-plus-content split.

CSS Grid is the deck plan. You define columns and rows at the same time, and every element gets placed into a specific cell — or made to span several cells — in that two-dimensional structure. It's built for laying out a whole page section, a photo gallery, a dashboard of cards, or anything where you're thinking in both directions at once rather than just "next in line."

Here's the rule of thumb Commander Byte drills into every cadet: if you're arranging things in one direction, reach for Flexbox. If you're arranging things in a grid — rows and columns together — reach for Grid. They aren't rivals; they're different tools for different shaped problems, and real pages usually use both — Grid for the big page structure, Flexbox for the smaller pieces inside each grid cell.

Like Flexbox, Grid is turned on with one declaration on a parent container. The difference is what happens next: instead of one axis to control, you get two axes, an explicit set of named tracks, and the ability to have an item deliberately overlap or span across several of them.

A 3-column, 2-row grid. Cyan dashed lines are column tracks, the pink dashed line is a row track. Cell 2 is told to span 2 columns, so it eats the space cell 3 would've occupied — that's Grid's two-dimensional placement in action.

Field Manual

Turning It On: display: grid

Exactly like Flexbox, Grid is switched on with one line on the parent element. The moment you do, that element's direct children become grid items, and the parent starts obeying Grid's placement rules instead of normal block-stacking.

CSS
.dashboard {
  display: grid;
}
WHAT JUST HAPPENED On its own, display: grid doesn't look like much — by default you get a single column, and children just stack in one row per item. The real power shows up once you define grid-template-columns and grid-template-rows, which is next.

Defining Columns & Rows

grid-template-columns and grid-template-rows describe the tracks of your grid — how many columns/rows exist and how wide/tall each one is. The fr unit means "one fraction of the remaining space," which makes flexible, responsive tracks trivial to write. repeat() saves you from typing the same track size over and over.

CSS
.dashboard {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;
  grid-template-rows: 200px 200px;
}

/* same columns, shorter to write */
.dashboard {
  grid-template-columns: repeat(3, 1fr);
}

/* mixed: a fixed sidebar + a flexible main area */
.layout {
  grid-template-columns: 220px 1fr;
}
WHAT JUST HAPPENED 1fr 1fr 1fr creates three equal-width columns that share the container's space evenly, and they reflow automatically if the container resizes — no percentages or math required. repeat(3, 1fr) is identical to typing 1fr three times. Mixing units — like 220px 1fr — pins one track to a fixed size and lets the other absorb whatever space is left, a very common sidebar pattern.
▸ DEEP DIVE: minmax() and auto-fit — grids that wrap themselves

repeat(auto-fit, minmax(150px, 1fr)) is one of the most useful one-liners in CSS. It tells the browser "fit as many columns as you can, each at least 150px wide, but let them stretch to fill leftover space" — and when the container gets too narrow to fit another column, it automatically wraps to a new row. No media query needed. This is the trick professional photo galleries and card grids use to be responsive without writing a single breakpoint.

Gap

gap works in Grid exactly like it does in Flexbox: consistent spacing between cells, in both directions, without margin hacks. You can also use row-gap and column-gap separately if you want different spacing on each axis.

CSS
.dashboard {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
WHAT JUST HAPPENED gap: 16px adds 16px of space between every column and every row of cells — but never on the outer edge of the grid. That distinction matters: gap is spacing between siblings, not padding around the container.

Spanning Items

Individual grid items can be told to occupy more than one track using grid-column or grid-row. The shorthand span N means "stretch across N tracks starting from wherever this item would normally land."

CSS
.featured-card {
  grid-column: span 2; /* eats the width of 2 columns */
}

.tall-card {
  grid-row: span 2; /* eats the height of 2 rows */
}
WHAT JUST HAPPENED This is the move that makes Grid feel different from Flexbox: one item can deliberately take up more room than its neighbors while everything else automatically reflows around it — a hero image spanning 2 columns in a gallery, a highlighted stat card spanning 2 rows in a dashboard. A very common bug: writing grid-row: span 2 when you meant grid-column: span 2 — one stretches sideways, the other stretches down, and it's an easy pair to mix up.

Named Areas

For whole-page layouts, grid-template-areas lets you literally draw the layout as ASCII art in your CSS, naming each region, then assign each child to a named region with grid-area.

CSS
.page {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-areas:
    "sidebar header"
    "sidebar main";
}

.sidebar { grid-area: sidebar; }
.header  { grid-area: header; }
.main    { grid-area: main; }
WHAT JUST HAPPENED Each quoted string in grid-template-areas is one row; each word inside it is one column's area name. Repeating sidebar across both rows tells the browser "this area spans both rows here" — that's how the sidebar becomes tall without touching grid-row at all. It reads almost like a diagram of the page, which is exactly the point.

⚠ COMMON MISTAKES

        
    
          
  • Forgetting display: grid on the parent — without it, grid-template-columns and friends do absolutely nothing.
    • 
          
  • Confusing grid-column with grid-row — one spans sideways, one spans downward, easy to swap by accident.
    • 
          
  • Reaching for Grid when the layout is really one-dimensional — a simple row of buttons is usually simpler as Flexbox.
    • 
          
  • Writing a fixed repeat(3, 1fr) and wondering why the gallery breaks on mobile — that's what auto-fit + minmax() is for.
    • 
          
  • Forgetting that gap only adds space between items, not around the outer edge of the grid — you still need padding for that.
