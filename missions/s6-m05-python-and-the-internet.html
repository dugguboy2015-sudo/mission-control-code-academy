Field Manual

Calling an API with requests

requests isn't built into Python — install it once with pip install requests — but it's the standard way Python talks to the web.

PYTHON
import requests

url = "https://api.open-meteo.com/v1/forecast"
params = {"latitude": 51.5, "longitude": -0.12, "current": "temperature_2m"}

response = requests.get(url, params=params, timeout=10)
response.raise_for_status()   # stop here if the server said 4xx/5xx

data = response.json()        # JSON text  →  Python dict
print(data["current"]["temperature_2m"])
WHAT JUST HAPPENED params builds the ?latitude=51.5&longitude=-0.12… part of the URL for you — no string gluing. timeout=10 means "give up after 10 seconds" instead of hanging forever. raise_for_status() is Python's version of checking response.ok from Mission 4.3: a 404 or 500 becomes a clear error instead of a confusing crash three lines later.

Navigating Nested Data

Real responses are nested: dictionaries inside dictionaries, lists of dictionaries inside those. Read them one level at a time, left to right.

PYTHON
city = WEATHER["location"]["name"]
now = WEATHER["current"]["temp_c"]
print(f"{city}: {now}°C right now")

for day in WEATHER["forecast"]:
    print(day["day"], day["high"], day["low"])
WHAT JUST HAPPENED WEATHER["current"] is itself a dictionary, so ["temp_c"] reaches one level deeper. WEATHER["forecast"] is a list of dictionaries — loop over it and each day is one dictionary. When you're lost in a big response, print one level at a time: print(WEATHER.keys()), then go deeper.

Missing Keys and Failed Requests

APIs leave fields out when they don't apply — a day with no weather alert simply has no "alert" key. And networks fail. Plan for both.

PYTHON
for day in WEATHER["forecast"]:
    alert = day.get("alert", "none")   # no KeyError if it's missing
    print(day["day"], "alert:", alert)

try:
    response = requests.get(url, timeout=10)
    response.raise_for_status()
except requests.exceptions.RequestException as err:
    print("Couldn't reach the weather service:", err)
WHAT JUST HAPPENED day["alert"] would crash with a KeyError on every calm day; day.get("alert", "none") quietly hands back the default instead. RequestException catches every way a request can fail — no connection, timeout, bad status — so your program can explain the problem instead of dumping a traceback.

Finding "the Best" Item with max()

max() with a key function (you'll lean on it again in the Sector 6 capstone) returns the whole item that wins, not just the winning number.

PYTHON
windiest = max(WEATHER["forecast"], key=lambda d: d["wind_kph"])
print(f"Windiest day: {windiest['day']} ({windiest['wind_kph']} km/h)")

⚠ COMMON MISTAKES

  • Treating a list like a dictionary: WEATHER["forecast"]["high"] fails — the forecast is a list, so pick a day first or loop.
  • Using d["alert"] on data where the key is sometimes missing — use .get().
  • Forgetting timeout=, so a slow server freezes your script forever.
  • Putting an API key straight into a script you then share or commit (Mission 7.3 explains the safe way).
