Field Manual

Slicing — Grabbing a Range of a List

list[start:end] pulls out a range of items, not including the item at end. Leave either side blank to mean "from the beginning" or "to the end." Negative numbers count backward from the end of the list.

PYTHON
crew = ["Nova", "Kip", "Zed", "Rell", "Juno"]

print(crew[1:3])   # ['Kip', 'Zed']
print(crew[:2])    # ['Nova', 'Kip']
print(crew[3:])    # ['Rell', 'Juno']
print(crew[-1])    # 'Juno' — last item
print(crew[::-1])  # the whole list, reversed
WHAT JUST HAPPENED crew[1:3] grabs index 1 up to (but not including) index 3 — two items. crew[-1] is a shortcut for "the last item" that avoids needing to know the list's length. crew[::-1] uses a third slicing number (the step) of -1, which walks backward through the whole list — a common Python idiom for reversing.

Sorting, Filtering & List Comprehensions

sorted() returns a new sorted list without changing the original; list.sort() sorts in place. A list comprehension — [expression for item in list if condition] — builds a new list in one line, and it's one of the most distinctly "Pythonic" tools in the language.

PYTHON
fuel_levels = [42, 18, 27, 65, 9]

print(sorted(fuel_levels))               # [9, 18, 27, 42, 65]
print(sorted(fuel_levels, reverse=True))  # [65, 42, 27, 18, 9]

low_fuel = [f for f in fuel_levels if f < 30]
print(low_fuel)  # [18, 27, 9]

doubled = [f * 2 for f in fuel_levels]
print(doubled)   # [84, 36, 54, 130, 18]
WHAT JUST HAPPENED low_fuel = [f for f in fuel_levels if f < 30] reads almost like English: "give me f, for every f in fuel_levels, but only if f is less than 30." It's exactly equivalent to a for loop that appends to an empty list — just written in one expression instead of four lines.
▸ DEEP DIVE: The equivalent for loop

The low_fuel comprehension above does exactly this, longhand: low_fuel = [], then for f in fuel_levels: if f < 30: low_fuel.append(f). Comprehensions aren't magic — they're a shorthand for a pattern you'll write constantly.

Nested Structures — Lists of Dictionaries

This is the pattern from the Briefing above, in real code. Looping over a list of dictionaries and pulling out one field from each is one of the single most common things you'll do with real data.

PYTHON
crew = [
    {"name": "Nova", "role": "Captain", "fuel_used": 42},
    {"name": "Kip", "role": "Engineer", "fuel_used": 18},
    {"name": "Zed", "role": "Navigator", "fuel_used": 27},
]

for member in crew:
    print(f"{member['name']} ({member['role']}) used {member['fuel_used']} fuel")

total_fuel = sum(member["fuel_used"] for member in crew)
print(f"Total fuel used: {total_fuel}")
WHAT JUST HAPPENED Each pass through the loop, member holds one whole dictionary, and member["name"] reaches inside it for one field — exactly like crew[0].name would in JavaScript, just with bracket syntax. sum(member["fuel_used"] for member in crew) is a generator expression — a comprehension without the square brackets, built specifically to be handed straight to a function like sum().

Dictionary Methods: .keys(), .values(), .items(), .get()

Three methods cover almost every way you'll want to loop over a dictionary, plus one safety method for reading a key that might not exist.

PYTHON
ship = {"name": "Voyager-9", "fuel": 84, "shields": True}

print(list(ship.keys()))    # ['name', 'fuel', 'shields']
print(list(ship.values()))  # ['Voyager-9', 84, True]

for key, value in ship.items():
    print(f"{key}: {value}")

print(ship.get("callsign", "UNKNOWN"))  # no crash — returns the default
WHAT JUST HAPPENED ship["callsign"] would crash with a KeyError since that key doesn't exist — ship.get("callsign", "UNKNOWN") instead returns a safe fallback. Reaching for .get() whenever a key's presence isn't guaranteed is a habit that prevents a huge share of real-world Python crashes.

Tuples & Sets — Two Specialized Cousins

A tuple — (1, 2, 3) — looks like a list but is immutable: once created, it can never be changed. It's used for fixed groupings, like coordinates. A set — {1, 2, 3} — is an unordered collection that automatically removes duplicates, perfect for "does this already exist?" checks.

PYTHON
coordinates = (12.5, -4.2)  # a tuple — won't change
# coordinates[0] = 99  # this line would crash — tuples are immutable

visited_systems = {"Kepler", "Theta", "Kepler", "Rigel"}
print(visited_systems)  # {'Kepler', 'Theta', 'Rigel'} — duplicate removed automatically
WHAT JUST HAPPENED Notice visited_systems only kept one "Kepler" even though it was added twice — that deduplication is automatic and is the entire point of a set. You won't reach for tuples and sets nearly as often as lists and dicts, but recognizing them (round brackets vs curly-with-no-colons) matters when you see them in other people's code.

⚠ COMMON MISTAKES

  • Using dict["key"] on a key that might not exist, crashing with KeyError instead of using .get().
  • Forgetting that list.sort() changes the list in place and returns None — printing its result directly prints None, not the sorted list.
  • Confusing a list of dictionaries ([{...}, {...}]) with a dictionary of lists ({"names": [...], "roles": [...]}) — they solve different problems.
  • Trying to modify a tuple after creating it — tuples are immutable by design; use a list instead if you need to change it.
