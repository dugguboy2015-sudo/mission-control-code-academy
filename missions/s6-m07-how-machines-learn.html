Build a Classifier From Scratch

Briefing

Field Manual

Features and Labels

Each example is a list of features (measurements) plus a label (the right answer). The model never sees "lemon-ness" directly — only numbers.

PYTHON
TRAIN = [
    (4, 2, "lemon"),   # (size, sweetness, label)
    (6, 8, "apple"),
    (9, 5, "orange"),
]
size, sweetness, label = TRAIN[0]
print(size, sweetness, label)   # 4 2 lemon
WHAT JUST HAPPENED Each example is a tuple — like a list that can't be changed. size, sweetness, label = TRAIN[0] "unpacks" it into three variables at once. Features should be on similar scales (both 1–10 here): if size were in grams (0–300) it would drown out sweetness completely.

"Similar" Means "Close": Distance

Plot two fruits as points. The straight-line distance between them (Pythagoras!) measures how different they are.

PYTHON
import math

def distance(a, b):
    return math.sqrt((a[0] - b[0]) ** 2 + (a[1] - b[1]) ** 2)

print(distance((0, 0), (3, 4)))   # 5.0
WHAT JUST HAPPENED a[0] - b[0] is the size difference, a[1] - b[1] the sweetness difference. Square both, add, square-root: the classic 3-4-5 triangle gives exactly 5. With more features (weight, color…) you just add more squared differences — the idea works in any number of dimensions, which is how Mission 7.5's embeddings measure similarity too.

k-Nearest Neighbours: Let the Closest Examples Vote

PYTHON
from collections import Counter

def predict(point, k=3):
    by_distance = sorted(TRAIN, key=lambda ex: distance(point, ex))
    nearest = by_distance[:k]
    votes = Counter(ex[2] for ex in nearest)
    return votes.most_common(1)[0][0]
WHAT JUST HAPPENED sorted(..., key=...) lines every training fruit up from most to least similar. [:k] keeps the closest k. Counter tallies their labels, and most_common(1) returns the winner, like [("lemon", 3)] — hence [0][0]. distance(point, ex) works on a 3-item tuple because it only reads positions 0 and 1. Using an odd k like 3 helps avoid ties.

Testing Honestly: Train vs. Test

A model that's only checked on the examples it learned from will look perfect — and tell you nothing. Keep some labelled examples back (a test set) and see how many it gets right.

PYTHON
correct = 0
for size, sweetness, truth in TEST:
    guess = predict((size, sweetness))
    print(f"({size}, {sweetness}) guessed {guess}, really {truth}")
    if guess == truth:
        correct += 1

print(f"Accuracy: {correct / len(TEST):.0%}")
WHAT JUST HAPPENED :.0% formats 0.75 as 75%. Expect mistakes — a model is only as good as its examples. If every apple you trained on was medium-sized, a giant apple will look like an orange. That's training-data bias, and it's the same reason real AI systems can be unfair to people their data under-represents.

⚠ COMMON MISTAKES

  • Measuring accuracy on the training data — of course it looks perfect; it has seen the answers.
  • Mixing feature scales (grams next to a 1–10 rating) so one feature silently dominates the distance.
  • Using an even k and getting a tied vote.
  • Believing a model is "smart" because it's often right — it only knows what its examples showed it.
