MISSION 8.2: THE AGENT LOOP

Reason → Act → Observe

Mission 7.4's tool calling was single-shot: one question, one tool call, done. An agent repeats that cycle — deciding what to do, doing it, and looking at the result — as many times as the task actually needs, using each result to inform the next decision. This loop, called ReAct (Reason + Act), is the single mechanism underneath every AI agent you'll ever build or use.

🔴 COMMANDER LEVEL ⏱ ~50 MIN 🛠 BROWSER ONLY
1

Briefing

Ask "what's 15% of $42, and is that within my $10 tip budget?" A single tool call can't answer this — it genuinely needs two steps, and the second step depends on the first step's actual result. An agent handles this by looping: Reason ("I need to calculate the tip first"), Act (call a calculator tool), Observe (the result comes back: $6.30), then reason again ("now I need to compare that to my budget") — repeating until it has enough information to give a final answer.

This loop repeats until the model decides it has enough information to give a final answer instead of taking another action.
2

Field Manual

Anatomy of One Loop Iteration

Each pass through the loop is exactly Mission 7.4's tool-calling pattern, run once: the model reasons about what's needed next, decides on an action (a tool call, from 7.4), your code executes that tool for real, and the tool's real result — the observation — gets added back into the conversation as new information for the next reasoning step.

JAVASCRIPT
async function runAgentLoop(goal, maxIterations) {
  const history = [];

  for (let i = 0; i < maxIterations; i++) {
    const step = decideNextStep(goal, history); // REASON

    if (step.type === "final") {
      return { answer: step.answer, iterations: i + 1 };
    }

    const observation = await callTool(step.tool, step.args); // ACT
    history.push({ ...step, observation });                   // OBSERVE
  }

  return { answer: null, iterations: maxIterations, stopped: "max iterations reached" };
}
WHAT JUST HAPPENED history is the growing record of everything the agent has done and observed so far — it gets passed into decideNextStep() every iteration, so each new decision is informed by every previous result. The loop only ends two ways: the model outputs a "final" answer, or the safety limit maxIterations is hit.

Stopping Conditions Are Not Optional

An agent that can act repeatedly and autonomously can also get stuck — repeating the same failing action, or never quite deciding it has enough information. maxIterations is a hard safety net: no matter what, the loop stops after a fixed number of steps. Without one, a buggy or confused agent can loop indefinitely, and — since every iteration is a real LLM call — burn real money (Mission 7.8) doing it.

THIS IS NOT A HYPOTHETICAL RISK A real-world agent with no iteration cap and a tool that returns a slightly-wrong result can loop for hundreds of calls trying to "fix" a problem that isn't actually fixable that way — a genuine, common failure mode. Mission 8.6 and 8.7 (evals and observability) exist specifically to catch this kind of thing before and after it happens.

Debrief / Cheat Sheet

ReActReason → Act → Observe, repeated
ReasonDecide what to do next, given history so far
ActActually execute the chosen tool call
ObserveFeed the tool's real result back into history
maxIterationsThe hard safety cap against infinite loops

⚠ COMMON MISTAKES

  • Building an agent loop with no iteration cap at all — a real risk of runaway cost and confused, repeated actions.
  • Forgetting to actually append the observation back into history — the agent then "forgets" what it just learned on the very next reasoning step.
  • Assuming the reasoning step is free — every iteration of a real agent loop is a genuine LLM call, with genuine cost (Mission 7.8).
  • Confusing a single tool call (Mission 7.4) with a full agent loop — a loop is defined by REPEATING reason-act-observe, not by using a tool once.
