MISSION 7.6: RAG

Retrieval-Augmented Generation — Chat With Your Own Notes

An LLM's knowledge is frozen at training time — it has never seen your personal notes, your company's internal documents, or anything written after training ended. RAG (Retrieval-Augmented Generation) solves this without retraining anything: retrieve the most relevant pieces of YOUR data using Mission 7.5's semantic search, stuff them into the prompt as context, and let the model answer using only what you handed it. This mission combines Missions 7.3 and 7.5 into the single most common real-world LLM application pattern.

🔴 COMMANDER LEVEL ⏱ ~70 MIN 🛠 BROWSER ONLY
1

Briefing

Ask a general-purpose LLM "when is my doctor's appointment?" and it will either refuse (it genuinely has no way to know) or — worse — hallucinate a plausible-sounding but made-up answer, exactly as Mission 7.1 warned. RAG never asks the model to know your private facts from memory. Instead, it finds the actual relevant text from your own notes first, and hands it to the model as part of the question.

This is genuinely the entire idea — the letters R, A, G literally name the three steps in order.
2

Field Manual

Chunking — Why You Split Documents Up First

Before anything gets embedded, real documents are split into smaller chunks — a paragraph or a few sentences each, not one giant embedding for an entire document. A single embedding is one point in space; cramming an entire long document into one vector blurs many different topics into a vague average, making retrieval far less precise. Several focused chunks, each embedded separately, let retrieval find the one specific paragraph that actually answers a question.

Building the Augmented Prompt

Once you've retrieved the most relevant chunk(s), you build a prompt that hands them to the model explicitly as context — and just as importantly, instructs it to stick to that context.

PROMPT TEXT
Answer the question using ONLY the context below.
If the answer isn't in the context, say you don't know — do not guess.

Context:
"Doctor's appointment rescheduled to next Tuesday at 3pm."

Question: When is my doctor's appointment?
WHAT JUST HAPPENED The model never "knew" your appointment time — Mission 7.5's retrieval step found the one relevant note out of possibly thousands, and this prompt hands it over directly. The explicit instruction "use ONLY the context" and "say you don't know" is doing real work: without it, the model may blend in outside knowledge or guess when the context is incomplete.

Why "Say You Don't Know" Is the Most Important Line

This single instruction is what keeps RAG grounded instead of just another hallucination risk. If retrieval genuinely found nothing relevant, a model without this instruction will often still produce a fluent, confident, completely made-up answer — exactly Mission 7.1's hallucination risk, now dressed up as if it were "sourced" from your data. Explicitly permitting "I don't know" as a valid answer is what actually prevents that.

The Full Pipeline, in Code

JAVASCRIPT
async function ragAnswer(question, chunks) {
  // 1. RETRIEVE — Mission 7.5's semantic search
  const relevant = semanticSearch(question, chunks, embed, 2);

  // 2. AUGMENT — build a grounded prompt
  const context = relevant.map(r => r.text).join("\n");
  const prompt = `Answer using ONLY this context. If it's not here, say you don't know.

Context:
${context}

Question: ${question}`;

  // 3. GENERATE — Mission 7.3's safe proxy call
  return await callYourProxy(prompt);
}
WHAT JUST HAPPENED Every single piece of this function is something you've already built in an earlier mission — semanticSearch and embed from 7.5, a proxy call from 7.3. RAG isn't new machinery; it's an assembly of tools you already have, in a specific, deliberate order.

⚠ COMMON MISTAKES

  • Embedding one giant document as a single chunk instead of splitting it into focused, individually retrievable pieces.
  • Forgetting to instruct the model to say "I don't know" when context is missing — without it, a model tends to guess instead of refusing.
  • Assuming RAG means the model was "trained" on your notes — it wasn't; the notes are just retrieved and inserted into the prompt fresh, every single query.
  • Retrieving too many irrelevant chunks "just in case," diluting the context and making it harder for the model to focus on what's actually relevant.
