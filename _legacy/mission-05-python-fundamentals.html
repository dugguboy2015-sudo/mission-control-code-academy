Second Language, Same Universe — Ground Control's Language of Choice

Everything you've built so far ran inside a browser, speaking JavaScript. But most of the software running the world — automation scripts, data pipelines, AI systems, the backend logic behind almost every app — runs somewhere else, and a huge share of it speaks Python. Briefing

Think of JavaScript and Python as two starships from the same fleet, built to the same command structure but manufactured by different shipyards. Both understand variables, functions, conditionals, and loops. Both can talk to files, networks, and data. But the syntax — the exact wording of the commands — is different, and Python has one rule that surprises almost everyone at first: indentation is not just style, it's structure.

In JavaScript, curly braces { } mark where a block of code starts and ends. In Python, there are no braces — the code block is defined purely by how far it's indented. Get the indentation wrong and your program doesn't just look messy, it breaks or does something different than you intended. This forces genuinely readable code as a side effect, which is part of why Python is so popular for large projects.

Python is also famous for reading almost like plain English — if x in list: instead of a symbol-heavy equivalent — which is exactly why it's the default choice for data science, automation, backend web frameworks, and a huge share of today's AI tooling.

Same logic, two dialects — Python drops the braces and semicolons entirely, relying on consistent indentation instead.

Field Manual

Printing & Indentation

print() is Python's equivalent of console.log() — it outputs text. There's no { } for blocks; instead, everything at the same indentation level belongs to the same block. The standard is 4 spaces per level.

PYTHON
print("Systems check initiated")

fuel = 8
if fuel < 10:
    print("WARNING: fuel critical")
    print("Recommend immediate refuel")
print("Check complete")
WHAT JUST HAPPENED The two indented print lines belong to the if block and only run when fuel < 10. The final print("Check complete") is back at the outer indentation level, so it always runs regardless of the condition. Notice: no semicolons, no curly braces — just the colon (:) that opens a block and consistent indentation that defines it.

Variables, Types & f-strings

Python variables need no let or const — you just assign directly. Types are still there (string, int, float, bool, list, dict), Python just doesn't make you declare them upfront.

PYTHON
ship_name = "Voyager-9"
thrust_power = 78
shields_up = True

print(f"{ship_name} is running at {thrust_power}% thrust")
WHAT JUST HAPPENED An f-string (the f right before the opening quote) lets you drop variables directly into text using {curly braces} — Python's equivalent of JavaScript's backtick template strings. Booleans are capitalized in Python: True and False, not lowercase like JavaScript.

Lists & Dictionaries

Python's list is the equivalent of a JavaScript array. Python's dictionary is the equivalent of a JavaScript object — labeled key/value pairs.

PYTHON
crew = ["Nova", "Kip", "Zed"]
print(crew[0])  # Nova
crew.append("Rell")

ship = {
    "name": "Voyager-9",
    "fuel": 84,
    "online": True
}
print(ship["fuel"])  # 84
WHAT JUST HAPPENED Lists index from 0, same as JavaScript arrays. .append() adds an item to the end. Dictionaries use square-bracket key access just like JavaScript objects with bracket notation (ship["fuel"]) — Python dictionaries don't support the dot notation (ship.fuel) that JavaScript objects allow.

Functions with def

Python functions are defined with def instead of function, and don't require a return type declaration — Python figures that out at runtime.

PYTHON
def calculate_fuel_needed(distance_light_years):
    fuel_per_light_year = 12
    return distance_light_years * fuel_per_light_year

fuel = calculate_fuel_needed(5)
print(fuel)  # 60
WHAT JUST HAPPENED Notice the naming convention: Python functions and variables traditionally use snake_case (underscores), while JavaScript prefers camelCase. Neither is more "correct" — they're just the accepted style in each language's community, and following the convention makes your code instantly readable to other engineers.
▸ DEEP DIVE: Default parameters

You can give a parameter a fallback value: def greet(name="Cadet"): — if no argument is passed, name becomes "Cadet" automatically. This is handy for optional settings without forcing every caller to specify everything.

Conditionals & For Loops

Python's for loop is built to iterate directly over items in a list — no manual index counting required, though you can still access an index with enumerate() when you need it.

PYTHON
crew = ["Nova", "Kip", "Zed"]

for member in crew:
    if member == "Kip":
        print(f"{member} is piloting today")
    else:
        print(f"{member} is on standby")
WHAT JUST HAPPENED for member in crew: reads almost like English — "for each member in crew." This runs the indented block once per item in the list, with member holding a different value each pass. Python's == works exactly like JavaScript's === — there's no separate loose-equality operator to worry about.

⚠ COMMON MISTAKES

  • Inconsistent indentation — mixing tabs and spaces, or indenting a line by accident.
  • Forgetting the colon (:) at the end of an if, for, or def line.
  • Using lowercase true/false instead of Python's capitalized True/False.
  • Trying to access a dictionary with dot notation (ship.fuel) instead of bracket notation (ship["fuel"]).
  • Forgetting that Python is case-sensitive: Crew and crew are two different variables.
