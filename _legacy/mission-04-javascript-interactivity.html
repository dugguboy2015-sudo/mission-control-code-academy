MISSION 04: JAVASCRIPT

Bringing the Ship to Life — Logic, Reactions, and Real Behavior

HTML gave your ship a hull. CSS gave it a paint job and a layout. Neither one can actually do anything — they're static. JavaScript is the onboard computer: it listens for events (a button press, a keystroke, a timer going off), runs logic to decide what should happen, and then reaches into the page to change it, live, without a reload. This is the mission where your pages stop being documents and start being applications.

🟡 OFFICER LEVEL ⏱ ~65 MIN 🛠 BROWSER ONLY
1

Briefing

Every interactive system — a spacecraft's autopilot, a video game, a web app — follows the same basic loop: something happens (an event), the computer decides what to do about it (runs a function), and then the world changes as a result (an action, often updating what's on screen). JavaScript is the language that lets a webpage run exactly this loop.

Unlike HTML and CSS, which describe things, JavaScript gives instructions — a sequence of steps the browser executes in order, complete with decisions ("if this, do that"), repetition ("do this 10 times"), and memory (variables that store values you can use later). This is a real programming language, the same core concepts you'd find in Python, and it's the language every web browser on the planet understands natively.

The part of a webpage JavaScript reaches into and changes is the DOM — the same nested tree structure from Mission 02. JavaScript can find any element in that tree, read it, and rewrite it, all while the page is running, with no reload required.

The core loop of every interactive app: something happens, code reacts, the page updates — and then it waits for the next event.

Field Manual

Variables & Data Types

A variable is a labeled storage container. Use let for values that will change, const for values that won't. JavaScript's core data types are strings (text), numbers, booleans (true/false), arrays (ordered lists), and objects (labeled bundles of data).

JAVASCRIPT
let thrustPower = 78;
const shipName = "Voyager-9";
let shieldsUp = true;

let crew = ["Nova", "Kip", "Zed"]; // array

let ship = { // object
  name: shipName,
  fuel: 84,
  online: true
};
WHAT JUST HAPPENED thrustPower is a number you can reassign later. shipName is locked with const — trying to reassign it throws an error, which is exactly the point: it protects values that should never accidentally change. Arrays use square brackets and index from 0 (crew[0] is "Nova"); objects use curly braces and named keys (ship.fuel is 84).

Functions — Reusable Instructions

A function is a named block of code you can run whenever you need it, optionally feeding it different inputs (parameters) each time.

JAVASCRIPT
function calculateFuelNeeded(distanceInLightYears) {
  const fuelPerLightYear = 12;
  return distanceInLightYears * fuelPerLightYear;
}

let fuel = calculateFuelNeeded(5);
console.log(fuel); // 60
WHAT JUST HAPPENED Defining a function doesn't run it — calling it does, with calculateFuelNeeded(5). The return keyword sends a value back out of the function so it can be stored or used elsewhere. Without return, a function completes silently and gives back undefined.
▸ DEEP DIVE: Arrow functions

You'll frequently see a shorter syntax called an arrow function: const calculateFuelNeeded = (d) => d * 12; does the same thing as the example above. It's especially common for short functions passed directly into other functions (like event handlers), which you'll see constantly.

Conditionals & Operators

Decisions in code are made with if/else statements and comparison operators like === (equals), >, <, and !== (not equal).

JAVASCRIPT
function checkFuelStatus(fuel) {
  if (fuel < 10) {
    return "CRITICAL: refuel immediately";
  } else if (fuel < 40) {
    return "LOW: plan a refuel stop";
  } else {
    return "NOMINAL";
  }
}
WHAT JUST HAPPENED JavaScript checks conditions top to bottom and runs the first block that matches — once one matches, it skips the rest. Always use === (three equals signs) instead of == for comparisons; === checks both value and type, avoiding a whole category of confusing bugs.

Finding Elements in the DOM

Before you can change something on the page, JavaScript needs to find it. document.querySelector() uses the exact same selector syntax as CSS.

JAVASCRIPT
const statusEl = document.querySelector("#status");
statusEl.textContent = "Systems nominal";
statusEl.style.color = "#4dffb4";
statusEl.classList.add("highlight");
WHAT JUST HAPPENED querySelector("#status") finds the first element matching that CSS selector and hands it back as an object you can manipulate. textContent changes visible text, .style changes inline CSS directly, and classList.add attaches a CSS class — usually the cleanest way to change appearance, since the actual styling rules stay in your CSS file.

Events — Reacting to the Cadet

addEventListener attaches a function that runs automatically whenever a specific thing happens to an element — a click, a keystroke, a form submission.

JAVASCRIPT
const launchButton = document.querySelector("#launchButton");

launchButton.addEventListener("click", function() {
  const statusEl = document.querySelector("#status");
  statusEl.textContent = "LAUNCH SEQUENCE INITIATED";
});
WHAT JUST HAPPENED Nothing runs immediately — the function inside addEventListener is stored and waits. Only when the cadet actually clicks #launchButton does the browser run it. This is the complete event loop from the briefing diagram, written as real code: event ("click") → function (the code in the braces) → DOM update (changing statusEl.textContent).

⚠ COMMON MISTAKES

  • Using == instead of === and getting surprising type-coercion bugs.
  • Forgetting return in a function and then wondering why the result is undefined.
  • Calling querySelector before the element exists on the page (script running too early).
  • Attaching an event listener with the wrong event name ("onclick" vs "click" as a string).
  • Reassigning a const — if a value needs to change later, it should have been let.

Quick check — what does document.querySelector("#status") return if no element on the page has id="status"?
