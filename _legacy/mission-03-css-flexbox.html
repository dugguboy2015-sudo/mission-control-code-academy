MISSION 03: CSS & FLEXBOX

Arranging the Bridge — Styling and Positioning Every Station

HTML built the hull and decided what exists. CSS is the control panel that decides how everything looks and where it sits. Colors, spacing, fonts, and — most importantly for real layouts — Flexbox, the system that lets you arrange elements in rows and columns that adapt to any screen size. This is the mission where your pages stop looking like a stack of index cards and start looking like something you'd actually ship.

🟡 OFFICER LEVEL ⏱ ~55 MIN 🛠 BROWSER ONLY
1

Briefing

CSS stands for Cascading Style Sheets. "Cascading" means rules can stack, override, and inherit from each other — and when two rules conflict, CSS has a precise, learnable system (called specificity) for deciding which one wins. You write rules as selectors (which elements to target) paired with declarations (what to change about them).

Every element on a page is secretly a rectangle, and every rectangle follows the same anatomy: content in the middle, surrounded by padding (breathing room inside the box), a border (the box's edge), and margin (space pushing other boxes away). This is called the box model, and understanding it explains 90% of "why is this spaced weirdly" bugs.

Once you can style individual boxes, the real question becomes: how do you arrange many boxes together? That's Flexbox — a layout mode where you tell a parent container "line your children up in a row" or "in a column," and then fine-tune how they're spaced, aligned, and resized. It's the single most useful layout tool in modern CSS.

The box model: content sits inside padding, padding sits inside the border, and margin pushes neighboring boxes away.
In a flex row, the main axis runs horizontally and the cross axis runs vertically — two different properties control each direction.
2

Field Manual

Selectors & The Cascade

A CSS rule is a selector followed by declarations in curly braces. You can target elements by tag name, by class (reusable, prefixed with a dot), or by ID (unique, prefixed with a hash).

CSS
p {
  color: #a8b3d1;
}

.status-card {
  background: #1b2540;
  border-radius: 8px;
}

#launch-button {
  font-weight: bold;
}
WHAT JUST HAPPENED p targets every paragraph. .status-card targets every element with class="status-card" — classes are meant to be reused across many elements. #launch-button targets the one element with id="launch-button" — IDs should appear exactly once per page.
▸ DEEP DIVE: Specificity — who wins when rules conflict?

If two rules target the same element with different values, CSS uses a scoring system: ID selectors beat class selectors, which beat tag selectors. An inline style="..." attribute beats all of them. When you're fighting a style that "won't apply," it's almost always a specificity fight — something more specific is overriding you.

Colors & Typography

Colors can be named (red), hex codes (#ff6ec7), or functions like rgb(). Typography properties control how text looks and reads.

CSS
h1 {
  font-family: 'Orbitron', sans-serif;
  font-size: 32px;
  color: #4ee1ff;
  letter-spacing: 0.05em;
}
WHAT JUST HAPPENED The font list is a fallback chain — the browser tries Orbitron first, then falls back to any generic sans-serif font if it isn't available. em is a relative unit (relative to the element's font size); px is an absolute unit. Both are legitimate — the choice depends on whether you want something to scale with text size.

Flexbox — Turning It On

Flexbox is activated on a parent element with one line, and it instantly changes how its direct children behave.

CSS
.control-panel {
  display: flex;
  flex-direction: row; /* or: column */
}
WHAT JUST HAPPENED display: flex turns .control-panel into a flex container. Every direct child immediately lines up in a row (the default) instead of stacking on top of each other like normal block elements. flex-direction: column flips that to a vertical stack.

Flexbox — Alignment on Both Axes

Once flex is on, two properties do most of the work: justify-content controls spacing along the main axis, align-items controls positioning along the cross axis.

CSS
.control-panel {
  display: flex;
  justify-content: space-between; /* main axis spacing */
  align-items: center;         /* cross axis alignment */
  flex-wrap: wrap;             /* allow overflow to drop to a new line */
}
WHAT JUST HAPPENED space-between pushes the first item to the start and the last to the end, distributing the rest evenly — a classic navbar pattern. align-items: center vertically centers everything regardless of height. Without flex-wrap: wrap, items would default to squeezing onto one line no matter how narrow the screen gets.

Play with all of these live in the Command Console below before moving on — this is a topic you learn by breaking it, not by reading about it.

Flexbox — Sizing Individual Items

You can also control how individual children grow, shrink, or take up space, rather than just how the group is arranged.

CSS
.sidebar {
  flex: 0 0 200px; /* grow shrink basis */
}

.main-content {
  flex: 1; /* grow to fill remaining space */
}
WHAT JUST HAPPENED flex is shorthand for three values: grow, shrink, and basis (starting size). A fixed sidebar plus a flex: 1 main content area is one of the most common real-world layout patterns you'll build — it's how dashboards, docs sites, and admin panels are structured.

⚠ COMMON MISTAKES

        
    
          
  • Setting display: flex on the wrong element — remember, it only affects direct children.
    • 
          
  • Confusing justify-content and align-items — one is main axis, one is cross axis, and they swap meaning when you flip flex-direction.
    • 
          
  • Using margins to space out flex items instead of the simpler, more consistent gap property.
    • 
          
  • Forgetting flex-wrap: wrap and wondering why items get squeezed into oblivion on small screens.
    • 
          
  • Fighting specificity instead of checking whether a more specific selector is overriding your rule.
