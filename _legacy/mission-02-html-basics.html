MISSION 02: HTML

Building the Hull — Structure for Everything You'll Ever Ship

Before a ship can fly, it needs a hull — a physical structure that holds every system in place. HTML is that hull for anything that runs in a browser. It doesn't make things pretty and it doesn't make things interactive; it defines what exists and how it's organized. Every website, every web app, every dashboard you'll ever build starts here.

🟢 CADET LEVEL ⏱ ~40 MIN 🛠 BROWSER ONLY
1

Briefing

Think of a webpage as a spacecraft cutaway diagram. The outer hull is the <html> element — everything lives inside it. Inside the hull there are two main compartments: the <head>, which holds systems the crew never sees directly (page title, metadata, links to stylesheets), and the <body>, which holds everything the crew — your visitors — actually see and interact with.

Inside the body, elements nest inside each other like compartments inside compartments: a navigation bar might contain a list, which contains list items, which contain links. This nested structure is called the DOM — the Document Object Model — and it's not just a visual idea. It's a real tree data structure that JavaScript can read and modify, and that CSS uses to decide what to style.

HTML elements are written as tags: an opening tag, some content, and a closing tag — <p>content</p>. Some elements, like images, are self-closing because they have no inner content: <img src="photo.jpg">. Getting the nesting right is non-negotiable — a browser will often try to guess what you meant if you get it wrong, and guessing is never a strategy you want your ship relying on.

Every element nests inside a parent — html contains head and body, body contains nav, main, and footer, and so on.
2

Field Manual

The Document Skeleton

Every HTML file starts with the same boilerplate. This tells the browser what version of HTML you're using and sets up the two main compartments.

HTML
<!-- Tells the browser: this is modern HTML -->
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Mission Log</title>
</head>
<body>
  <h1>Status: Nominal</h1>
</body>
</html>
WHAT JUST HAPPENED <!DOCTYPE html> isn't a tag — it's an instruction to the browser about which rules to follow. lang="en" tells screen readers and search engines what language the page is in. <title> sets the text shown in the browser tab, not anything visible on the page itself.

Text Elements — Headings & Paragraphs

Headings (h1 through h6) create a hierarchy of importance — h1 is the most important heading on the page, and there should generally only be one. Paragraphs hold body text.

HTML
<h1>Mission Control Code Academy</h1>
<h2>Cadet Roster</h2>
<p>Training begins at 0800 hours. Bring your own terminal.</p>
WHAT JUST HAPPENED The browser automatically renders h1 largest, h2 smaller, and so on down to h6. This isn't just styling — screen readers use heading levels to build a navigable outline of your page, so skipping levels (going from h1 straight to h4) actually breaks accessibility.

Links, Images & Attributes

Most tags accept attributes — extra information written inside the opening tag as name="value" pairs. Links and images depend entirely on attributes to function.

HTML
<!-- href: where the link goes. target="_blank": open in new tab -->
<a href="https://nasa.gov" target="_blank">Visit NASA</a>

<!-- src: image file location. alt: description for screen readers -->
<img src="rover.jpg" alt="Mars rover on the surface" width="300">
WHAT JUST HAPPENED <img> has no closing tag or inner content — it's a "void element." The alt attribute isn't optional decoration: it's what screen readers announce, and it's what shows if the image fails to load. Never ship an image without one.
▸ DEEP DIVE: Relative vs. absolute paths

src="rover.jpg" is a relative path — it looks for the file next to your HTML file. src="https://example.com/rover.jpg" is an absolute URL pointing anywhere on the internet. Relative paths are what you'll use constantly once you start organizing real projects into folders like /images and /scripts.

Lists & Containers

Lists group related items. Generic containers — <div> for block-level grouping, <span> for inline grouping — exist purely to organize structure so CSS and JavaScript have something to target.

HTML
<ul>
  <li>Check fuel levels</li>
  <li>Verify comms link</li>
  <li>Confirm crew status</li>
</ul>

<div class="checklist-card">
  <p>All systems <span class="status-ok">GO</span></p>
</div>
WHAT JUST HAPPENED <ul> (unordered list) needs <li> children — use <ol> instead when order matters (step 1, step 2...). The class attribute doesn't do anything by itself; it's a label that CSS or JavaScript can later hook into to style or control that exact element.

Semantic Elements — Naming Things Honestly

You could build an entire page out of nothing but <div>. It would work. It would also tell a screen reader, a search engine, or another engineer absolutely nothing about what each section means. Semantic elements — header, nav, main, article, footer — behave like div visually but carry real meaning.

HTML
<header><h1>Mission Control</h1></header>
<nav><a href="#">Home</a></nav>
<main>
  <article><h2>Mission 02: HTML</h2></article>
</main>
<footer><p>© Academy</p></footer>
WHAT JUST HAPPENED Nothing visually changed compared to using all divs — but now a screen reader can jump straight to "main content," a search engine can tell your article from your navigation, and any engineer reading this file understands the layout instantly, without needing comments.

Debrief / Cheat Sheet

<html>Root element, wraps everything
<head>Invisible metadata & setup
<body>Everything visible on the page
<h1>–<h6>Headings, in order of importance
<p>A paragraph of text
<a href="...">A link
<img src="..." alt="...">An image
<ul> / <ol> / <li>Unordered / ordered lists
<div> / <span>Generic block / inline containers
<header><nav><main><footer>Semantic layout elements

⚠ COMMON MISTAKES

  • Forgetting to close tags, or closing them in the wrong order (e.g. <b><i>text</b></i>).
  • Skipping heading levels (jumping from h1 to h4) instead of nesting them in order.
  • Leaving alt off images — a screen reader user gets nothing useful there.
  • Using a div for everything when a semantic element already exists for that purpose.
  • Forgetting quotes around attribute values: src=photo.jpg instead of src="photo.jpg".
